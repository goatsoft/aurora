# AGENTS.md

Instructions for AI agents and humans working in this repo. Scope and priorities live in the [Aurora roadmap](https://github.com/orgs/goatsoft/projects/2) project and its [issues](https://github.com/goatsoft/aurora/issues); check there before starting work. Decisions are recorded in [docs/adr](docs/adr).

## What this is

Aurora: a GOATsoft library for WebGPU-only animated backgrounds with a generated CSS fallback, plus Aurora Studio (builder), `@goatsoft/color` (shared OKLab maths), gruff (our static site generator) and the aurora.goatsoft.io site. One repo holds all of it.

## Stack

- **Node 24** (`.nvmrc`), **pnpm 10** workspaces (`packages/*`, `apps/*`), ESM only.
- **TypeScript 5.9**, strict (`noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`). Typecheck is `vue-tsc -b` over project references, so `.vue` files are checked too.
- **Vite 8** library mode builds each package to `dist/`; `tsc` emits declarations.
- **Vitest 4**: `unit` project (Node) and `browser` project (Playwright Chromium with real WebGPU via SwiftShader).
- **ESLint 10** flat config: typescript-eslint strict + stylistic type-checked, eslint-plugin-vue (recommended) for SFCs, perfectionist for import order, better-tailwindcss for classes, and **ESLint Stylistic for formatting**. There is no Prettier; `pnpm lint:fix` fixes order and formatting.
- **Changesets** for versioning; `@goatsoft/*` publishes to npm with provenance from `release.yml` (ADR-0010).
- **Valibot** for `.aurora` validation; **fast-check** for fuzz tests.
- **Vue 3.5** (peer) and **unplugin 3** for the bindings; `vue-tsc` checks `.vue` files in apps.
- **Studio**: vue-router 5 file routes, unplugin-auto-import / -vue-components / -icons (Hugeicons), reka-ui styled shadcn-style with Tailwind 4, motion-v. Its components are tested in the `studio` Vitest project (browser, in `pnpm test:apps`), which extends Studio's Vite config.
- **gruff**, our static site generator, builds the site and docs on `unplugin-vue-markdown` (ADR-0008).

## Layout

```
packages/color    @goatsoft/color           OKLab/OKLCH, sRGB/P3, gamut mapping, ΔE-OK, CSS colour parsing (0 deps)
packages/format   @goatsoft/aurora-format   .aurora schema, validation, migrations
packages/core     @goatsoft/aurora          WebGPU runtime, WGSL composer, CSS fallback; /element is <aurora-bg>, /load is loadAurora
packages/vue      @goatsoft/aurora-vue      <AuroraBackground>, useAurora(), <AuroraScene> (`<script setup>` SFCs)
packages/unplugin @goatsoft/aurora-unplugin .aurora imports: build-time validation, typed modules, HMR
packages/gruff    @goatsoft/gruff (private) Markdown → Vue pages, live aurora fences, search, prerender (ADR-0008)
apps/sample       Vite + Vue SSR app using all of the above
apps/studio       Aurora Studio, the builder (vue-router 5 file routes, reka-ui + Tailwind 4, motion-v)
apps/site         aurora.goatsoft.io: landing page, /docs from docs/, hosted Studio at /studio/
assets/brand/     The Aurora logo, favicons and brand sheets (not MIT: LICENSE-ART.md)
presets/classic/  The classic presets: the parity reference and default demo themes
presets/mono/     The GOATsoft mono pack: goatsoft.io's grayscale auroras, dark and light
presets/starters/ One starter per generator (generated by packages/core/test/docs.test.ts)
presets/scenes/   Art-directed multi-layer scenes, each with a golden image
presets/interactions/ Art-directed input playgrounds, with rest and interaction-frame goldens
docs/generators/  Generator reference, generated from each generator's param specs
docs/adr/         Architecture decision records (in the repo only, not on the site)
```

Each package: `src/index.ts` entry, tests in `test/`. Packages export a `@goatsoft/source` condition pointing at `src/`, so cross-package imports use sources and tests never need a build. Use the package name (`@goatsoft/aurora-format`), never a relative path into another package.

## Commands

```sh
pnpm install
pnpm dev             # the site on localhost:5180 with Studio at /studio/, as deployed; its Studio link edits this repo's .aurora files
pnpm verify          # lint + typecheck + tests with coverage + build + app tests + size budgets. Must pass before every push.
pnpm test:apps       # apps/* against the built packages, and Studio's component tests (run after pnpm build)
pnpm lint:fix        # fixes lint and formatting
pnpm test            # unit tests
pnpm test:browser    # WebGPU browser tests (needs `pnpm exec playwright install chromium` once)
AURORA_CHROME=1 pnpm test:browser   # the same, in the installed Google Chrome instead of Playwright's Chromium
pnpm --filter aurora-studio dev   # Studio on localhost, with dev-tool mode on this repo's .aurora files
pnpm coverage
pnpm test -u         # regenerate snapshots, including packages/format/schema/v1.json
pnpm size            # gzip sizes against the budgets below
pnpm changeset       # for any user-facing change to a @goatsoft/* package
pnpm consumers       # pack the packages, check the tarballs, and build a fresh project with them in every bundler
```

## North star

Aurora must be very, very slick. It should blow people away visually and in its DX. Every change is judged against that: no visual glitches, beautiful defaults, errors that say exactly what is wrong and how to fix it, types that autocomplete everything.

## Engineering bars

- **No visual glitches.** No flash of an empty canvas and no layout shift. The swap from the CSS fallback to WebGPU crossfades in about 300 ms, and device loss recovers without the page noticing.
- **Accessibility.** Reduced motion is honoured everywhere. Backgrounds are always `aria-hidden`. Studio is fully keyboard operable and passes WCAG AA.
- **Performance.** Paused off-screen and in hidden tabs, one GPU batch per tick, and budgets checked in CI.
- **Truthfulness.** The runtime never claims WebGPU before a real frame has rendered.

## Budgets

- **Size**, minified with dependencies bundled and gzipped. `pnpm size` measures them and `pnpm verify` fails when one is over; `scripts/size.ts` holds the list.
  - Main-thread runtime and worker: 10 kB each.
  - Lazy interaction modules (controller, physics and bindings, with dependencies): 7 kB.
  - `@goatsoft/aurora/element`: 14 kB, since it carries the format's generated Valibot validator; editor metadata is excluded (ADR-0012).
  - Each generator: 2 kB. The shared noise library: 3 kB, shipped once however many generators use it.
- **Runtime.** One worker and one GPU device per page, a shared 30 fps budget, frames gated on the previous submit completing, and 0.5x device pixel ratio capped at 1280 px per axis, all configurable through `configureAurora({ fps, pixelRatio, maxPixels })`. First frame within 100 ms of attach on an M1.
- **Site.** Lighthouse 100 in all four categories on desktop. On mobile, 100 for accessibility, best practices and SEO, and at least 99 for performance (ADR-0008). CLS at most 0.01.

## Rules

### Git

- **Git flow.** `main` is releases, `develop` is integration. Work on `feature/<short-name>` (or `fix/…`, `release/…`, `hotfix/…`) branched from `develop`; PRs target `develop`.
- **Never** create `claude/…` or other agent-named branches.
- Never push directly to `main` or `develop`, and never force-push a shared branch.
- Conventional commits: `feat(core): …`, `fix(format): …`, `chore: …`, `ci: …`, `docs: …`.
- Don't put model names or identifiers in commits, PRs or code.

### Releasing

- A release is a `release/<version>` branch from `develop`, merged into `main` by PR with a **merge commit** (not squash). `release.yml` runs CI on `main`, then opens a "Version Packages" PR from the pending changesets; merging that PR runs `scripts/publish.ts`, which publishes the `@goatsoft/*` packages to npm through trusted publishing (no token, provenance included) and creates a tag and GitHub Release for each. `pages.yml` deploys the site from the same pushes.
- After each release, merge `main` back into `develop` with a merge commit (versions, changelogs, consumed changesets). Squashing either merge cuts `develop` off from `main`'s history, and the back-merge then conflicts on every released file.
- Never publish by hand: only the workflow publishes, so every version carries provenance. `node scripts/publish.ts --dry-run` checks what would be published.
- The `@goatsoft/source` condition and `src/` are never published. Run `pnpm consumers` after changing a package's `exports`, `files`, `bin`, build config or dependencies: it checks the packed tarballs and builds a fresh project with each supported bundler.
- The site must be deployed before a release whose packages point at new hosted URLs (badges, schema).

### Code

- Formatting: 2 spaces, single quotes, no semicolons. Run `pnpm lint:fix`; don't hand-format.
- `import type` for type-only imports, and every type import comes first. Then `node:` built-ins, packages, `~/` and `@/`, relative paths, and side-effect imports such as CSS, each sorted (lint enforces it).
- Tailwind classes in their canonical form (`min-h-svh`, not `min-h-[100svh]`) and in Tailwind's order, with no unknown, duplicate or conflicting classes. Lint checks them against each app's own `src/main.css`.
- **No `<style>` blocks or decorative inline styles in SFCs. Dynamic CSS custom properties driven by component state (for example, a comparison divider) are allowed.** Style with Tailwind 4 (PostCSS) classes. Published components may only bind styles computed by core (`FILL_STYLE`, the compiled CSS fallback), since they can't rely on a consumer's Tailwind build.
- No parent-relative paths (`../`; lint enforces it). In tests and apps, `@/x` is the current package's `src/x` and `~/x` is the repo root (`~/presets/classic/hero.aurora`); filesystem code uses `inject('root')` in tests or Vite's `searchForWorkspaceRoot()`. Package `src/` uses same-folder `./` imports only, because aliases would leak into published declarations.
- WebGPU only. No WebGL or GLSL path, ever; the fallback is CSS.
- `.aurora` files are declarative JSON and must never carry executable code or WGSL.
- Colours are authored and mixed in OKLab/OKLCH; `mix: "srgb"` exists only for bit-exact parity with the classic presets. All colour maths goes in `@goatsoft/color`; never reimplement it elsewhere.
- Never report WebGPU (`data-aurora="webgpu"`) before a real frame has rendered.
- Respect the [budgets](#budgets) (core < 10 kB gzip, each generator < 2 kB).
- Backgrounds are always `aria-hidden` and honour `prefers-reduced-motion`.

### Tests

- New behaviour gets a test. Anything touching the GPU gets a `*.browser.test.ts`.
- Never skip, disable or loosen a test to get green; fix the cause.
- `@goatsoft/color` and `@goatsoft/aurora-format` stay at 100% coverage (enforced by `pnpm verify`). Use fast-check for round-trip and fuzz properties.
- Error messages are part of the API: assert their exact text.
- Golden images are generated and compared under the same (SwiftShader) adapter.
- Headless SwiftShader can't present WebGPU canvases: render through `TextureCanvas` (packages/core/test/gpu.ts) to check pixels. Classic parity is bit-exact; keep it that way.
- Auroras are the flagship: new defaults, docs and demos start from the aurora presets.
- **Generators are art-directed.** Every generator has a golden image (`packages/core/test/golden/<id>.png`, regenerate with `UPDATE_GOLDEN=1 pnpm test:browser`) and must look beautiful with its defaults and palette before it ships. Review motion, not just a still: render several frames.
- Generator docs and starters, modifier schemas/docs, and runtime validators are generated: change their source, then `pnpm test -u`. The public authoring schema retains metadata; runtime validators derive from its syntax tree (ADR-0012).
- Studio saves documents as authored: the classic presets must stay byte-identical to what Studio writes (apps/studio/test/document.test.ts).
- Band-limit fine detail: work out the pixel footprint from `ctx.res` and fade or widen anything periodic before it aliases.

- Dependencies are managed by the maintainer. Don't add, remove or upgrade them without being asked. `playwright` is pinned exactly so local and CI Chromium match.
