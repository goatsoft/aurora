# ADR-0002: The `.aurora` format

Status: accepted · 12 October 2026

## Context

A `.aurora` file is what Studio exports and every GOATsoft site imports. It has to be safe to load from anywhere, pleasant to write by hand, and able to change without breaking files already in the wild.

## Decision

- **Declarative JSON, never code.** No WGSL, JavaScript or CSS rules. Generators are referenced by id (`"aurora-fbm"`) and configured by params. The hand-tuned CSS fallback accepts single `<image>` values only: `; { } < > @ \` and `url()`/`image-set()` are rejected, so a file can't inject styles or load resources.
- **Strict keys.** Unknown keys are errors, not silently dropped, so typos surface immediately (`$.layers[0].blnd is not a known key. Did you mean "blend"?`). `$schema` is allowed for editor support.
- **Valibot is the single source of truth.** One schema gives runtime validation, the TypeScript types (`AuroraInput`, `AuroraDocument`) and the published JSON Schema (`schema/v1.json`, generated by a snapshot test; regenerate with `pnpm test -u`). Field descriptions live in the schema, so editors show them on hover.
- **Errors are for humans.** Every issue has a JSONPath and a sentence that says what is wrong and, where possible, how to fix it. `parseAurora` never throws and reports every issue at once; `assertAurora` throws one `AuroraFormatError` listing them.
- **Defaults are filled on parse.** Files can stay minimal; code always sees a complete `AuroraDocument`.
- **Integer versions with forward migrations.** `MIGRATIONS[n]` upgrades version `n` to `n + 1` and is never edited after release. Files from a newer version fail with an "upgrade @goatsoft/aurora-format" message rather than being misread. `parseAurora` reports the `sourceVersion` so tools can offer to save an upgraded file.
- **Canonical serialisation.** `stringifyAurora` writes a fixed key order, 2-space indent and a trailing newline, so Studio exports diff cleanly and parse → stringify is stable.

## Consequences

- Adding a field is a minor change if it is optional with a default; renaming or removing one needs a version bump and a migration.
- Generator param schemas live with the generators (Phase 2), so the format validates params only as numbers, booleans or strings. The runtime validates them against the generator.
